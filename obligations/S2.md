# S2 independent backend portion

This is a partial S2 delivery on `s/S2-independent-rules`, based on S1 commit
`382537a`. It is separate from S1's PR #2. S1 models, migrations and tests are
unchanged. No additional dependency or schema migration is needed.

## Implemented

- `catalogue.py`: fresh copies of a draft rule payload. Table 1.4 amounts in
  integer paise, leased-property multiplier, ten-year term, 15-day proof period,
  penalty rates, path/document checklist configuration, operational reminder
  thresholds and escalation matrix. No exemptions are inferred automatically.
- `rules.py`: schema validation, explicit version/date selection and detached,
  frozen rule snapshots. Every calculation/finding can identify the source,
  version and canonical SHA-256. No implicit query for the latest policy.
- `calculations.py`: pure amount calculation, term anniversary, explicitly
  supplied holdings coverage and human-review penalty proposals.
- `checks.py`: `AMOUNT_SHORTFALL`, `TERM_GAP`, `PROOF_OVERDUE`, using the existing
  Finding representation, with `obligations-v3-draft` provenance. They remain
  advisory and are not plugged into portal acceptance or old audit snapshots.
- `seed_obligation_rules`: explicit, atomic, idempotent creation of an unapproved
  demo rule version. A conflicting stored version is rejected, never updated.

## Source and policy limits

The catalogue was checked against the government-hosted APH 2024-27:
https://cdnbbsr.s3waas.gov.in/s35938b4d054136e5d59ada6ec9c295d7a/uploads/2025/03/2025031399.pdf

References: printed page 10 (Table 1.4 and 1.12), page 31 (2.25(f)), page 27
(2.21(h)-(i)), pages 61-62 (6.46), page 73 (7.7). The 10%/20% late-proof bands
are specifically the planning document's 2.25(f) interpretation. This is not
verification of all current addenda, different regulatory instruments or case
applicability. Bureau confirmation remains required. Every payload is labelled
`DRAFT_DEMO_NOT_APPROVED`, and seeding leaves `approved_by` null.

The command's effective window is caller-supplied for demo evaluation; it is
not a claimed statutory effective date. Reminder recipients and SLA thresholds
are team proposals. No emails, notifications, clearance tasks or decisions are
created. `WORKING` clock entries require Kushagra's calendar/scheduler integration.

## Calculation contract

`required_amount(approvals, ruleset, *, as_of, institution_type='PRIVATE')`
accepts `ApprovalInput` snapshots with canonical programme codes from the
catalogue and `DIPLOMA`/`UG`/`PG` levels. Select the applicable approval once per
programme/level; duplicates, unknown tenure and unsupported cells raise
`RuleInputError`. Either leased land or leased building doubles the aggregate
once for PRIVATE input. The caller must establish applicability and exemptions;
the calculator does not treat GOVERNMENT/UNIVERSITY as automatic exemption.

`term_end(start, ruleset, *, as_of)` computes a calendar anniversary. February 29
maps to February 28 in a non-leap end year, an explicit demo convention requiring
policy review. It does not update an obligation or grant an extension.

`coverage(obligation, as_of, *, holdings)` accepts `ObligationInput` and a complete
list of `HoldingInput` snapshots. `holdings=None` fails explicitly (`TODO(Y1)`);
an explicitly empty list means a known empty ledger. Each holding must match
both institution and obligation; duplicates are rejected. Only ACCEPTED,
non-superseded, non-released holdings count, with issue/maturity dates inclusive.
Expired, future-issued and pending holdings do not count toward today's held sum.

Continuous coverage is evaluated from `max(as_of, term_start)` through term end.
It stops at the first uncovered interval, even if a future top-up later repairs
the gap. A redundant short holding does not shorten sufficient longer coverage.
`term_gap_days` is the remaining term from that first break, not the sum of all
uncovered days. Unknown requirement/term remains unknown. This is an evaluation
of the supplied current administrative snapshot, not historical reconstruction
or independent confirmation of the holdings.

`obligation_findings(...)` additionally accepts explicit intimation and receipt
dates for payment proof and Affidavit-3. Missing intimation means unknown deadline,
not an invented one. The deadline is inclusive; overdue starts the following day.
Both receipts must exist to clear an outstanding proof flag. Late completed proof
can be assessed separately by `penalty_proposal`. Future receipts are rejected.

`penalty_proposal(...)` returns PROPOSED, NOT_DUE or REQUIRES_AUTHORITY_REVIEW.
Late-proof cutoffs need an explicit approval cycle year. Cross-year ambiguity and
post-July cases are not converted into automatic penalties/withdrawals. Fractions
round half-up to paise as a demo convention. Human confirmation always remains
required; this function does not debit funds or create S5 penalty workflow rows.

## Reproduce

```powershell
.\.venv\Scripts\python.exe manage.py test obligations.tests --verbosity 1
.\.venv\Scripts\python.exe manage.py test portal.tests --verbosity 0
.\.venv\Scripts\python.exe manage.py test --verbosity 0
.\.venv\Scripts\python.exe manage.py check
.\.venv\Scripts\python.exe manage.py makemigrations --check --dry-run
```

Optional local synthetic demo seed (after S1 migrations):

```powershell
.\.venv\Scripts\python.exe manage.py seed_obligation_rules --effective-from 2026-01-01 --effective-to 2026-12-31
```

Use `--rule-version 2` to create a new version. Repeat with identical options:
unchanged. A changed payload/window under the same
code/version: command error, unchanged DB. Choose a new version deliberately.
The command does not require a server, network, API key, DRF or React.
